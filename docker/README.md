# docker/

- `images.yaml` - **the image catalog**: every third-party container image
  the repo uses (manifests, Helm values, docker-compose on the VMs,
  Dockerfiles, test scripts, upstream Helm charts, k3s), each pinned to a tag
  and digest. Our own `ghcr.io/raiseofeasv/*` images aren't listed:
  `build.yml`/`deploy.yml` pin those per environment.
- `base/` - our central base images (`base-go`, `base-node`), see
  `base/README.md`.

## Changing an image version

1. Edit `tag` and `digest` in `images.yaml`. Get the digest with
   `docker buildx imagetools inspect <image>:<tag> --format '{{json .Manifest}}' | jq -r .digest`.
2. `just images-sync` rewrites every reference in the repo.
3. Open a PR. CI runs `just images-check` (any reference that disagrees with
   the catalog, or an image that isn't in it, fails) and scans the changed
   entries with Trivy, failing on a CRITICAL vulnerability that has a fix.

Adding a new third-party image: add it to `images.yaml` first, then
reference it anywhere; `just images-sync` refuses images it doesn't know.

Changes to the upstream charts' versions (`charts:`) are applied by re-running
the `helm install`/`upgrade` command in the component's README, which
`just images-check` keeps at the catalog's `--version`.

## Renovate

`.github/workflows/renovate.yml` runs Renovate every Monday (or on demand:
Actions -> Renovate -> Run workflow). For the catalog it bumps `tag` and
`digest` together, runs `python3 tools/images.py sync` in the same branch,
and opens one PR per week ("image catalog") that updates every reference.
Catalog PRs always wait for a human review.

## Scanning

Every night the prod `vuln-scanner` scans all catalog images that have a
digest (plus everything running in its namespace) and files the results in
Cerberoast: new vulnerabilities become findings with the image repository as
the asset, and findings no longer reported are closed automatically. The
list it scans is `infra/helm/vuln-scanner/scan-images.yaml`, generated by
`just images-sync`.
